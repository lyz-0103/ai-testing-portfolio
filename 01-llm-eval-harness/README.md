# 校园问答助手 LLM 评测集

给一个「校园智能问答助手」场景下的 LLM 应用做批量评测。60 条用例 + 自动化评测脚本 + 评测报告，跑测对象是任意 OpenAI 兼容接口（Qwen / GLM / DeepSeek 等）。

完整的评测思路和设计取舍写在 [docs/评测方案设计.md](./docs/评测方案设计.md)，这里只放结论和用法。

## 快速开始

```bash
# 离线自检（不需要 API Key，验证脚本逻辑，内置 3 条植入 badcase）
python3 eval_runner.py --mock

# 真实模型（任意 OpenAI 兼容接口）
export API_KEY="sk-xxx"
export BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
export MODEL="qwen-turbo"
python3 eval_runner.py

# CI 门禁：通过率低于 90% 时退出码为 1
python3 eval_runner.py --mock --fail-under 90
```

零第三方依赖，Python 3.8+ 直接跑。

## 目录结构

```
01-llm-eval-harness/
├── eval_cases.json          # 60 条用例（正常40/边界10/恶意10），带分类、手法标注、判定字段
├── eval_runner.py           # 评测脚本：批量跑测、判定、报告、明细导出、CI 门禁
├── docs/评测方案设计.md      # 设计文档：分类依据、判定规则取舍、已知局限
├── report.md                # 最近一次跑测的报告
└── results/latest.json      # 全量明细（含每条延迟），用于两次跑测之间 diff
```

## 迭代记录

- **v0.1（20 条）**：跑通「用例 → 批量跑测 → 报告」闭环。这版吃了关键词误报的亏，单个宽泛词（如"开放"）经常误判。
- **v0.2（44 条）**：关键词改成名词性信息词；给正常场景加"过度拒答"检测——收紧安全策略后正常问题的误拒率会悄悄上涨，不单独统计发现不了。
- **v0.3（60 条）**：补齐指令遵循子类（格式约束 + 长度校验）；恶意用例覆盖 5 种注入手法并单独标注；新增延迟统计、results 明细导出、`--fail-under` CI 门禁。

## 已知局限

关键词判定抓不住"事实错误但用词正确"的回答，这个盲区计划用 LLM-as-judge + 人工抽检校准解决（见设计文档第六节）。评测集按已知失败模式设计，存在过拟合风险，对策是线上 badcase 持续沉淀 + 盲测集。
